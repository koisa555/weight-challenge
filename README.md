# 4人减脂挑战赛 · 实时共享看板

一个**零依赖**的全栈小网站：任何人、任何设备，用同一个链接报体重，数据都汇总到服务器同一个数据库，所有人的排名/曲线/奖项实时同步。

## 目录结构
```
weight-challenge/
├── server.js      # 后台（Node 原生 http，无需 npm install）
├── index.html     # 前端看板页面
├── data.json      # 数据库（自动生成/更新，存全部体重记录）
├── package.json
└── README.md
```

## 一、本地运行（先自己试试）
需要 Node.js 18+（本机一般已装）。
```bash
cd weight-challenge
node server.js
# 浏览器打开 http://localhost:3000
```
开两个浏览器标签（或一个隐身窗口）分别报体重，能看到彼此的数据实时同步。

## 二、部署到免费云平台（让朋友也能用）
本地只能你自己电脑访问。要让 4 个人在不同设备都能用，**必须部署到一个有公网地址的服务器**。推荐用 Render（免费、有网页后台、最省心）。

### 用 Render 部署（约 5 分钟，新手友好）
1. 把 `weight-challenge` 整个文件夹上传到 GitHub（新建一个仓库，把 4 个文件传上去）。
2. 打开 https://render.com 注册（可用 GitHub 登录）。
3. 点 **New → Web Service** → 关联你的 GitHub 仓库。
4. 设置：
   - **Build Command**：留空（或填 `npm install`，无依赖其实可省）
   - **Start Command**：`node server.js`
   - **Instance Type**：选 **Free**
5. 展开 **Advanced → Add Environment Variable**（可选但推荐）：
   - 键 `PORT` → 值 `10000`（Render 要求的端口）
   - 键 `PASS` → 值 `你自己设的一个口令`（别人改数据要填这个；不填则任何人都能改）
6. 点 **Create Web Service**。等一两分钟，Render 会给一个地址，形如 `https://xxxx.onrender.com`。
7. 把这个地址发给 4 个人，大家打开就是同一个共享看板。

> 其他等价选择：Railway、Fly.io、Koyeb 等，步骤类似（上传代码 + `node server.js` 启动）。
> 国内访问 Render 有时偏慢，可选 Koyeb/Railway；或部署到任意支持 Node 的服务器。

### 想用口令保护编辑（防链接泄露被乱改）
部署时设置了环境变量 `PASS=某个词` 后，任何**写入**（报体重/改初始值/重置）都需要带这个口令：
- 网页里「编辑口令」输入框填上它即可正常保存；
- 没填或填错 → 报“编辑口令错误”，拒绝修改。
- **查看**永远公开，不影响大家看排名。
> 没设 `PASS` 也能用，只是任何人拿到链接都能改数据（4 人小群通常无所谓）。

## 三、日常使用
- **报体重**：选日期 → 4 人各填 → 点「💾 保存今日体重」即上传服务器。
- **看别人更新**：页面每 30 秒自动同步；也可手动点「🔄 同步最新数据」。
- **改初始体重**：管理员在「⚙️ 调整初始体重」里改，全队同步重算。
- **备份/恢复**：「⬇️ 导出备份」下载 JSON；「⬆️ 导入备份」可把备份合并回服务器。
- **重置**：「↺ 重置为初始数据」会把服务器数据清回 Excel 初始值（需确认）。

## 四、数据存在哪
所有数据在服务器上的 `data.json`。只要这个文件在，数据就在；换设备、换浏览器都不丢。建议偶尔「导出备份」存一份到微信/云盘，以防服务器重置。

## 五、常见问题
- **为什么不直接发之前的 .html 文件？** 那个是纯前端文件，数据只存在你自己浏览器里，别人打开是空白副本，无法共享。本版本有后台数据库，才能真正多人同步。
- **手机能用吗？** 能，页面自适应手机；用手机浏览器打开链接即可报体重。
- **需要我（丹婷超莹之外的人）会编程吗？** 不需要。部署是一次性操作；之后所有人只需要在浏览器里填数字。
